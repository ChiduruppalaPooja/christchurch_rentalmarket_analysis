## 1. Objective

Link the cleaned Christchurch Airbnb data to the cleaned Tenancy Services bond data so that short-term and long-term rentals can be compared by area and time. The brief asked us to:

- create a Koordinates account and API key;
- find the Stats NZ area-code layer on Koordinates and note its layer ID;
- query the API with each Airbnb latitude/longitude pair to get an area code that matches the bond data, testing a single query first;
- add the area code as a new column and save the enriched dataset so the queries do not need to be re-run;
- join both datasets on area code and time using a suitable join type;
- find the median Airbnb price in Christchurch Central (Location ID `326600`);
- find where the gap between short-term and long-term rental prices is largest;
- compare the number of Airbnbs and rental properties in each location (extension: compare beds); and
- optional extension: store both datasets in SQLite and use SQL for the join.

## 2. What we achieved

- Every Airbnb row (28,795 of 28,795) was assigned a Stats NZ **SA2 2019** area code through the Koordinates Query API.
- The enriched Airbnb dataset and a reusable coordinate lookup cache were saved locally, so the API only needs to be queried for new coordinates.
- Airbnb and tenancy data were joined on **SA2 code + quarter**, giving **408 matched area-quarter rows**.
- **Christchurch Central median Airbnb price: $237 per night** (equal-listing median across the study period).
- **Largest short- vs long-term price gap: Wigram South**, at about **$288.29 per night**.
- Airbnb listing counts were compared with tenancy bond counts by area, with a presentation chart for April–June 2026.
- The optional SQLite extension was completed: seven tables in `christchurch_rental_market.sqlite`.

## 3. Data used

| Input | Description |
|---|---|
| Cleaned Airbnb data | Christchurch City listings, October 2025 – June 2026 (28,795 monthly listing rows) |
| Cleaned tenancy data | Tenancy Services detailed quarterly bond data, filtered to the study quarters |
| Geography | Stats NZ *Statistical Area 2 2019 (generalised)*, Koordinates layer **`98970`** |
| API | Koordinates vector-query endpoint: `https://datafinder.stats.govt.nz/services/query/v1/vector.json` |

**Why SA2 2019 and not a newer layer:** Tenancy Services states that its bond data uses SA2-2019 area definitions. A newer boundary release could change codes or boundaries, so the codes would no longer line up with the tenancy `Location Id`.

## 4. How we did it

### Step 1: Query the API for area codes (`R/05_query_geography.R`)

1. Read the API key from `KOORDINATES_API_KEY` in a local `.Renviron` file. This file is git-ignored and the key is never committed.
2. Extracted the **unique** latitude/longitude pairs, rounded to six decimal places, because the same listing appears in many monthly snapshots.
3. Ran **one test query** before starting the full run.
4. Queried the remaining coordinates in batches of 100, using up to four parallel workers on macOS/Linux, with up to three retries per failed request.
5. Wrote a **cache after every batch**, so an interrupted run can resume. API failures and genuine "no polygon" results are recorded separately.
6. Joined the SA2 code and name back onto every monthly Airbnb row and saved the enriched dataset.

Each request uses `radius=0`, so the polygon must contain the exact point, plus `max_results=1` and `geometry=false`, because only the attributes are needed.

### Step 2: Align time periods

Airbnb data is monthly and tenancy data is quarterly, so each Airbnb month was mapped to the first day of its quarter:

| Airbnb months | Comparison quarter |
|---|---|
| October – December 2025 | `2025-10-01` |
| January – March 2026 | `2026-01-01` |
| April – June 2026 | `2026-04-01` |

### Step 3: Join the datasets (`R/06_integrate_rental_data.R`)

Joining the raw rows directly would have been many-to-many: many listings per area-month against many dwelling-type and bedroom categories per area-quarter. That would duplicate rows in both datasets. Instead:

1. **Airbnb:** one row per listing per quarter (that listing's median observed price), then one row per SA2 + quarter (the median across listings). Each listing therefore counts once, however many months it appears in.
2. **Tenancy:** one row per SA2 + quarter, using the source's `Dwelling Type = ALL` / `Number Of Beds = ALL` record.
3. The two summaries were joined with an **`inner_join` on `sa2_code + comparison_quarter`**. An inner join fits because a price gap can only be calculated when both sources have a value for the same place and quarter.
4. Unmatched keys on both sides were saved to separate anti-join tables so they are not lost silently.

Listing-quarters that were assigned to more than one SA2 are kept and flagged, but are excluded from area prices and counts. This geography-eligibility rule and the equal-listing weighting were added as corrections in Week 10 (D6).

### Step 4: Answer the analysis questions

- **Price gap:** Airbnb nightly price minus tenancy weekly median rent ÷ 7, by area and quarter, then the median gap per area across quarters.
- **Count comparison:** unique Airbnb listings vs total, active and closed bonds per area and quarter.
- **Charts** (`R/08_week9_plots.R`): built from the saved summary tables, so no API key is needed.

### Step 5: Optional SQLite database (`R/07_build_database.R`)

The database-ready tables were written to `data/processed/christchurch_rental_market.sqlite`.

## 7. Limitations and open items

1. **Different price units.** Airbnb prices are advertised nightly prices; tenancy figures are weekly bond-based rents. Dividing weekly rent by 7 allows a simple comparison but does not make the two markets equivalent.
2. **Missing Airbnb prices.** December 2025 – February 2026 have no observed prices in the source files, so those quarterly medians do not cover three complete months.
3. **Bond data caveats.** The bond data is subject to Tenancy Services privacy rounding and suppression, and its figures are provisional.
4. **Ambiguous geography.** Listing-quarters with more than one observed SA2 are excluded from area comparisons, but their monthly records are kept for review.
5. **Earlier documentation differs.** The Week 9 documentation reports some tenancy figures from an earlier version of the cleaning code (for example, 26,991 tenancy rows). This report uses the current output tables.

## 8. How to reproduce

From the RStudio project root, after copying `.Renviron.example` to `.Renviron`, adding the Koordinates API key and restarting R:

```r
source("R/00_setup_packages.R")
source("R/03_tenancy_prepare.R")      # if the processed tenancy file is not present
source("R/05_query_geography.R")
source("R/06_integrate_rental_data.R")
source("R/08_week9_plots.R")
source("R/07_build_database.R")       # optional SQLite extension
```

`R/02_airbnb_combine.R` is only needed to rebuild the combined Airbnb file from the nine raw monthly files, which are not stored on GitHub.
