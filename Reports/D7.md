## 1. Objective

Automate the data-wrangling pipeline so that new data can be added with one command. The brief asked us to:

- apply what we learned about automation in Week 10 to our pipeline;
- download the New Zealand `listings.csv` (not `listings.csv.gz`) for **July and August 2026** from Inside Airbnb;
- preprocess the new months with **one function call**, ideally from the command line;
- add the new months to the previous analyses and produce updated plots; and
- automate and orchestrate the existing code rather than redo everything.

## 2. What we achieved

- **One command** runs the whole pipeline: `Rscript run_pipeline.R`. In RStudio, `run_pipeline()` does the same and returns the results.
- The July (scraped 12 July 2026) and August (13 August 2026) New Zealand summary listings are **downloaded automatically** if missing, then verified and checksummed.
- The team's existing cleaning, SA2 2019 lookup, integration, SQLite and plotting scripts are **reused in dependency order**. No cleaning rules were rewritten.
- The study period now covers **11 monthly snapshots** (35,796 listing-month rows, 4,264 distinct listing IDs).
- **Three new monthly plots** were added, and the two existing comparison plots were regenerated.
- **60 automated checks pass**: 23 automation tests, 22 integration tests, 4 database tests and 11 saved-result checks.
- Unchanged stages are **cached and reused**, and the new results are written to separate period-specific folders, so earlier deliverable outputs are not overwritten.
- The pipeline found that the tenancy file **does not yet cover July–September 2026**. It reports this rather than inventing a comparison.

## 4. How we did it

### The controller (`run_pipeline.R`)

`run_pipeline()` performs these steps in order:

1. **Loads settings** from `config/automation.R`: the study period (October 2025 – August 2026) and the source and output folders.
2. **Checks the environment**: valid YYYY-MM months, the expected eleven monthly filenames, and the required packages. Packages are never installed silently.
3. **Downloads missing months.** Each file is downloaded to a temporary path, checked as a valid CSV, then moved into `data/raw/`. Files already present are not downloaded again. MD5 checksums are recorded, and byte-identical files labelled as different months are rejected.
4. **Passes run-specific settings** to the existing scripts through `options(rental.pipeline.overrides = ...)`, which `R/pipeline_config.R` reads. The scripts keep their original defaults when run on their own.
5. **Runs each stage with caching.** Each `stage()` declares its inputs, outputs and script. A stage is reused only if its inputs, code, settings, package versions and outputs all match the last checkpoint. Otherwise it is re-run.
6. **Chooses the latest genuinely matched quarter** for the comparison chart, rather than assuming the new months have tenancy data.
7. **Runs all tests and writes a report.** SUCCESS is reported only after both finish. Logs and a run-status file record RUNNING, FAILED or SUCCESS.

### Pipeline stages

| Stage | Script | What it does |
|---|---|---|
| 1 | `R/02_airbnb_combine.R` | Reads all 11 monthly files, filters to Christchurch, labels months, combines rows and applies the existing cleaning |
| 2 | `R/03_tenancy_prepare.R` | Applies the existing tenancy cleaning, selects the available study quarters and reports missing ones |
| 3 | `R/04_airbnb_summary.R` | Saves numeric and categorical summaries and missing-value counts |
| 4 | `R/05_query_geography.R` | Looks up SA2 2019 codes for new coordinates and reuses the cache for known ones |
| 5 | `R/06_integrate_rental_data.R` | Builds listing-quarter and area-quarter tables and joins Airbnb and tenancy on SA2 + quarter |
| 6 | `R/07_build_database.R` | Rebuilds the seven SQLite tables atomically (rolls back on failure) and checks the SQL join against R |
| 7 | `R/08_week9_plots.R`, `R/11_monthly_update_plots.R` | Regenerates the comparison charts and creates the new monthly charts |
| Validation | `tests/test_automation.R`, existing tests, `R/09_validate_pipeline.R` | Unit tests on small examples plus independent base-R recalculation of saved results |
| Report | `R/12_automation_report.R` | Writes `RUN_SUMMARY.md` from the saved results |

### Keeping the equal-listing method

The same listing can appear in several monthly snapshots, so the Week 10 weighting rule was kept:

- **Monthly chart:** one row per listing per month, so each listing counts once in that month's median.
- **Quarterly area comparison:** one median price per listing per quarter, then the median across listings.

## 7. Limitations and open items

1. **No tenancy data for Q3 2026.** The tenancy filename says Q3-2026, but the latest `TimeFrame` in the data is `2026-04-01` (April–June). July and August are fully processed and charted, but they have no tenancy match. Older rents are not carried forward.
2. **Q3 is incomplete.** July and August are two months of Q3; September is not included.
3. **Missing prices remain missing.** December 2025 – February 2026 have no observed prices in the source files.
4. **Extreme prices are kept.** For example, the $43,654 price stays in the data pending the team's review. The histogram's 99th-percentile view limit is not a cleaning rule.
5. **The pipeline runs on demand only.** There is no scheduled run or GitHub Actions CI. The source list covers July and August; future months must be added to `config/airbnb_sources.csv`.
6. **Prerequisites.** The October–June raw files and the raw tenancy file must already be in `data/raw/`. New coordinates need a Koordinates API key in `.Renviron`.

## 8. How to reproduce

From the project root (open `christchurch_rentalmarket_analysis.Rproj` first):

```sh
Rscript run_pipeline.R
```

Or, in the RStudio Console, to keep the results in the Global Environment:

```r
source("run_pipeline.R")
results <- run_pipeline()
View(results$monthly_summary)
```

To rebuild every stage instead of reusing the cache, use `Rscript run_pipeline.R --force` or `run_pipeline(force = TRUE)`. If packages are missing, run `renv::restore()` first.
