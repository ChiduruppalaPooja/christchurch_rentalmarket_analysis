## 1. Objective

Clean both datasets so they are ready to be combined in D5. The brief asked us to:

- clean the Christchurch Airbnb dataset from D3, dropping columns where sensible but keeping latitude and longitude;
- document each decision, the reason for it and its consequences (for example, rows lost);
- save the cleaned dataset locally and push the code so every team member can reproduce exactly the same file, keeping it space-efficient;
- download the Tenancy Services *Detailed quarterly report, 2020–2026* rental bond data and document its source and columns;
- filter the bond data to the same months as the Airbnb data;
- clean the bond dataset, keeping `Location Id` and `TimeFrame`; and
- keep the columns needed to compare rental prices and numbers of available properties next week.

## 2. What we achieved

- **Airbnb:** cleaned dataset of **28,795 rows × 15 columns**. **No rows were removed.** Four columns were dropped, nothing was imputed, and latitude and longitude were kept.
- **Tenancy:** all 12 source columns were kept. The text value `"NULL"` in the five rent columns was converted to a true missing value and those columns were made numeric. Nothing was imputed and no rows were removed during cleaning.
- **Tenancy study period:** filtered to the three quarters matching the Airbnb data, giving **27,212 rows**.
- Every cleaning decision is protected by checks in the code. The scripts stop or warn if the data no longer matches the documented findings.

## 4. How we did it

### Airbnb cleaning (`R/02_airbnb_combine.R`, sections 7–17)

Each column with missing values was investigated before any decision was made.

| Finding | Decision | Reason |
|---|---|---|
| `price` is missing for every listing in Dec 2025, Jan 2026 and Feb 2026, and for about 5–8% of listings in other months | **Keep as NA.** Do not impute. | A systematic source-level gap; there is no information to recover the true prices. |
| `minimum_nights` is missing in 37 rows | **Keep as NA.** Do not impute. | Too few to justify guessing a value, and there is no basis for one. |
| `last_review` and `reviews_per_month` are missing in 2,627 rows, all with `number_of_reviews = 0` | **Keep as NA.** Do not replace with zero. | The missingness is structural: a listing with no reviews has no last-review date. |
| `license` is missing in every row (code comment: 28,795 of 28,795) | **Remove column.** | It contains no information. |
| `host_name` is missing in one row (code comment) | **Remove column.** | Host names are not needed for the rental-market comparison. |
| `name` (listing title) | **Remove column.** | Descriptive text, not needed for the quantitative analysis. |
| `neighbourhood_group` | **Remove column.** | Every row is Christchurch City after filtering, so it is redundant. |
| The same listing ID appears in several months | **Keep.** | Each row is the listing at a different monthly snapshot. Only duplicates *within* a month would be errors. |
| High prices (maximum $43,654) | **Keep.** | Inspected rather than removed. High prices are not automatically errors. |

The code turns the documented findings into checks. For example, it warns if the months with 100% missing prices change, if missing `last_review` occurs on reviewed listings, or if `license` is no longer completely empty. It also stops if:

- the row count changes during column removal;
- any fully duplicated rows exist;
- a listing appears more than once in the same month;
- a listing ID is missing or empty;
- a price is negative or not a finite number; or
- the expected monthly snapshots are not all present.

### Tenancy cleaning (`R/03_tenancy_prepare.R`)

The script first checks the file and its 12 required columns, then inspects each column:

| Column(s) | Finding | Decision |
|---|---|---|
| `TimeFrame` | Stored as a date, no missing values, continuous quarterly sequence | No change |
| `Location Id` | Numeric IDs always have six digits; the source also contains the special codes `-99` and `NULL` | Kept unchanged. The code comments say their meaning cannot be established from the dataset alone, so they are not removed or recoded. |
| `Dwelling Type` | Six categories (ALL, House, Flat, Apartment, Room, Boarding House), none missing | No change |
| `Number Of Beds` | Mix of numbers and the meaningful categories `ALL` and `5+`; some values missing | Kept as text so `ALL` and `5+` survive. Missing values kept, not imputed. |
| `Total`, `Active`, `Closed Bonds` | No missing or negative values; `Total ≠ Active + Closed` for most rows | Kept as supplied. The additive relationship is not imposed. |
| Five rent columns | Stored as text because the source uses `"NULL"`; no other non-numeric values; no negative values; genuine zeros in `Log Std Dev Weekly Rent` | `"NULL"` converted to `NA`, then columns converted to numeric. Zeros kept. No imputation. |
| Reporting key | Each `TimeFrame + Location Id + Dwelling Type + Number Of Beds` combination is unique | No change |

The script then:

1. saves the **full cleaned dataset** (all quarters);
2. filters it to the study period (`TimeFrame` from 2025-10-01 to 2026-06-01, i.e. the quarters starting October 2025, January 2026 and April 2026); and
3. saves the **study-period dataset**, checking that no columns or study-period `Location Id` values were lost and that no rows fall outside the date range.

## 7. Limitations and open items

1. **Airbnb prices** are unavailable for December 2025 – February 2026, so price analysis for those months is not possible.
2. **Extreme prices are kept.** For example, $43,654 is retained pending further review.
3. **Special `Location Id` codes** (`-99` and `NULL`) remain in the tenancy data. They do not match any SA2 code, so they drop out at the D5 join rather than being removed here.
4. **Bond counts** do not satisfy `Total = Active + Closed`. The source values are used as supplied.
5. **Earlier documentation differs from the current code.** The existing cleaning documents describe an earlier version: 17 Airbnb columns, and `-99`/`NULL` tenancy rows removed (26,991 rows). This report follows the current code and its outputs.
